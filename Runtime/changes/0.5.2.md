# Runtime Change: 0.5.2 — Attempt-driven scanning and repeatable classification

Version: 0.5.2

> [English](0.5.2.md) | [简体中文](0.5.2.zh.md)

## Problem

Clock skew, scheduling drift, single-sample NAT verdicts and permanent exhaustion reduce punching opportunities.

## Recorded changes

<a id="patch-18"></a>
### Patch 18

0.5.2 returns NAT4 scanner round/phase advancement from wall clock to punch_attempt counts. Wall-clock scheduling did not actually synchronize the endpoints: measured clocks differed by 3.65 seconds, or 14 ticks, so bands differed. The main loop achieved about 3.1 ticks/s instead of the nominal 4; every missed wall-clock tick left a permanent coverage hole. Measured rotating-band coverage was only 78%–81%, and the initial band was the farthest, least likely one. Attempt-driven bands are consecutive and move outward; budget exhaustion only loses the farthest, least likely tail.

<a id="patch-19"></a>
### Patch 19

0.5.2 wakes the punching loop on fixed deadlines. Previously select waited 250 ms and last_punch_ms was then reset to the current time, adding roughly 65 ms of processing to each period. Advance by whole ticks and set the select timeout to the remaining time before the next punch; realign only after a stall longer than one tick.

<a id="patch-20"></a>
### Patch 20

0.5.2 classifies NAT by a majority over five samples instead of one A/B difference. A single transient rebinding could permanently label NAT3 as NAT4 because complete locked the original result without retesting, selecting the wrong punching strategy. Substantial disagreement produces uncertain and prefers layered, which covers the range in 63 ticks without depending on correct role assignment.

<a id="patch-21"></a>
### Patch 21

0.5.2 removes the permanent latch after punching-budget exhaustion. Previously punch_exhausted could be reset only by toggling manual relay, giving each peer just one lifetime opportunity. Retry after cooldown, for at most eight rounds. From 0.5.3 both endpoints use the same cooldown and realign through a same-generation supernode plan, without relying on MAC jitter.
