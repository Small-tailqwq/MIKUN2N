# Runtime Change: 0.5.8-9 — NAT 探测、协助链路证据与接口恢复

Version: 0.5.8-9

> [English](0.5.8-9.md) | [简体中文](0.5.8-9.zh.md)

## 问题

探测引起的重绑定误判锥形 peer，聚合计数无法定位协助超时，失效接口仍被优先选择又阻碍 IPv6 恢复。

## 改动记录

<a id="patch-53"></a>
### 补丁 53

0.5.8-9：避免 NAT 探测干扰自身结果，并让锥形 peer 保持协调打洞。探测曾在数据 socket 尚未联系 B 前，要求观察者 A 从端口 B 向该 socket 映射发送 XREPLY。会自行响应这类包的路由器（ICMP 端口不可达）随后为该 socket 的 B 流分配新公网端口，使每组 A/B 样本都不同；worker 校准为 CONE、且 A 端口与 supernode 观察一致的锥形 NAT 被报告为 NAT4 eim=0/5。某台此类路由器还收不到发往新 B 端口的回复，虽然服务端抓包确认观察者响应了全部请求，探测却一直为 unknown，未上报 NAT 摘要。双方回退到未协调的本地角色，六轮仅重叠一次、约两秒，随后停止。
过滤测试改在一次性 socket 上运行，数据 socket 只向 A、B 发送 PROBE。保留 supernode 的 REGISTER_SUPER_ACK 对数据 socket 的观察作为第三个样本：B 静默四秒后，用 A 与该端口比较判定，按一个样本上报并由 supernode 接受，让计划不再依赖 B。Cone↔NAT4 每个失败轮次交替使用已校准 worker bank 和 layered 扫描，从 bank 开始，因为此前被误判的锥形 peer 只有通过 bank 才连上 NAT4；一次 bank 协调错过后在同轮回退扫描。面对 layered 锥形 peer 的 anchor 随对方扫描结束，保持重试对齐。get_nat 增加 observed_port_sn 和 partial。Supernode 需要此版本才能规划 Cone↔NAT4 bank 轮次；旧版会使这些轮次在一次协调超时后回退。线格式和 IPv6 第 3 代不变。tools/tests-nat.c 覆盖分类结果，以及双方和 supernode 在每一轮的一致性；真实配对尚未验证。
同时修复上游 sock_to_cstr 传给 inet_ntop 的长度超过缓冲区的问题。glibc 加固版 inet_ntop 因此中止，使由 0.5.8-2 或后续源码构建的 Linux supernode 在格式化 IPv6 socket 时触发 “buffer overflow detected”；现场服务在启动 38 秒后退出。Windows 构建不受影响，其实际输出一直能放入缓冲区。

<a id="patch-54"></a>
### 补丁 54

（0.5.8-9）协助转发 Minecraft 流量可能超时，而小型探测仍响应。事件中的全局计数显示收到 3,039 个分片、仅完成 1,310 次重组，这个差额不能证明丢包或槽位耗尽。增加按线路／方向累计的 DATA 计数，将心跳单独计数，覆盖提交、封装检查到 TAP 写入；另增加按外层 peer 的 IPv6 提交与重组拒绝计数。普通日志保留有界汇总及生命周期／重置快照，get_peer_assists 暴露方向性计数供诊断记录。槽满、过期／缺失字节、重复／冲突及重放窗口计数用于区分本地重组压力和缺失的接收阶段。UDP 提交成功仍不能证明交付。四个槽位、两秒过期、线格式和传输选择均不变。这是为下一次三主机复现补充观测，并不声称已确定或修复历史超时的原因。

2026-10-11 审阅修正将日志字段 `checked_bytes` 和 `wire` 显式转换为 `unsigned`，
匹配 `%u`；诊断数值和传输行为保持原样。[协助技术契约](../../docs/PEER-ASSIST.zh.md)
同时明确：管理查询以存在本地协助电路为前提，成功和失败快照沿用相同的状态变化／
定期记录规则，并通过会话诊断记录器写入。Windows 原生重建及现有 `tests-ipv6`、
`tests-wire` 检查通过。本次修正未进行实机连接或运行时日志格式复现。

<a id="patch-55"></a>
### 补丁 55

（0.5.8-9）旧接口仍报告首选地址但路由器／上游已失效时，恢复 IPv6 选择。此前即使其他 Wi-Fi 接口可用，重连仍选择同一个低 metric 地址。保留工作中的绑定；已有 STUN／基础 peer 检查持续失败时允许尝试其他接口，启动宽限为三十秒，失败接口冷却六十秒。大探测丢失、瞬时队列压力、空闲或不兼容 peer 不触发轮换。新 socket 必须成功绑定后才退役旧 socket；枚举或替换失败不丢弃已有绑定。重新绑定更新 IPv6 路径证明与候选查询，保留 IPv4。普通日志标明接口、地址和原因。不增加并发路径，不改变第 3 代协议，也不要求 supernode 升级。此前事件没有保留能确定精确原因的复现，真实路由器故障和 Wi-Fi 恢复尚未验证。
