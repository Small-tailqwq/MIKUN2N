# Runtime Change: 0.5.8-10 — Supernode input and identity boundaries

Version: 0.5.8-10

> [English](0.5.8-10.md) | [简体中文](0.5.8-10.zh.md)

## Problem

A two-byte TCP length prefix of `0xffff` wrapped the expected frame length
before the receive bound was checked, so the next receive wrote past the frame
buffer.
Connections without registration or a completed frame could retain admission
slots indefinitely. Relayed payloads were not bound to the claimed source MAC's
registered transport. Federation membership could be introduced by a sender
knowing its name instead of being limited to operator-configured peers.

## Recorded changes

<a id="patch-56"></a>
### Patch 56

TCP lengths are decoded into `size_t` and checked before addition. The existing
2048-byte total-frame limit is retained: the two-byte prefix leaves at most 2046
body bytes. Bodies shorter than the common header are rejected. Every receive
requires `position < expected` and bounds the target by both the frame cap and
actual buffer capacity. Split prefixes/bodies and consecutive frames retain the
same state transitions.

Accepted connections have 60 seconds to register; an incomplete frame has 15
seconds from its first byte. These are monotonic deadlines checked at the next
loop pass (the select wait is at most ten seconds). Only a successful local
registration bound to that connection clears the initial deadline. Registered
idle clients keep the existing registration-expiry mechanism. Overflow accepts
are closed, allocation failure closes the new descriptor, and POSIX descriptors
outside `FD_SETSIZE` are rejected before `FD_SET`.

Local PACKET relay requires the source MAC's registration to match its sending
socket and observed endpoint. Closing a TCP connection invalidates remaining
registrations bound to it; a validated transport change updates the binding even
when its IP/port is unchanged. Authenticated registration remains the path for
NAT rebinding. This does not turn open communities into private ones or change
optional payload encryption.

Federation traffic must come from an explicitly configured `supernode.peer`
IP/UDP-port pair. Both sides must configure each other; DNS peers use resolved
addresses. Unknown REGISTER_SUPER senders and federation messages without the
supernode flag are rejected. With no configured peers, federation is closed.
ACK-advertised peers do not extend the allowlist, and ACK cookies are checked
before updating membership. Matching federation names remain necessary. This is
an endpoint allowlist, not cryptographic protection against spoofed allowed
sources, on-path traffic or compromised trusted servers. Automatic member
discovery is removed in favour of explicit operator control.

<a id="patch-57"></a>
### Patch 57

Wire-supplied `auth.token_size` is validated against `N2N_AUTH_MAX_TOKEN_SIZE`
before the fixed-size token field is filled, in REGISTER_SUPER,
UNREGISTER_SUPER, REGISTER_SUPER_ACK and REGISTER_SUPER_NAK decoding. The
backup-supernode array count in REGISTER_SUPER_ACK is bounded by the caller's
payload buffer. Without these checks a single unauthenticated UDP datagram
could copy up to about two kilobytes of attacker data past the 48-byte token
field on the `process_udp` stack.

## Companion coordinator

The v7.3.2 reference coordinator binds an active ID to an endpoint and a random
ownership token for rebinding. REPORT7 cannot create a member or replace one
from another endpoint without its token. The client keeps the token in memory
and checks the server source for coordination replies. Production observation
units select `--observer-only`, which preserves PROBE/PROBE7/XPROBE and does not
create experimental rooms. See the [reference protocol](../../tools/natpunch/README.md).

## Validation and deployment

Local native and reference-client builds, the existing wire/IPv6 and coordinator
regressions, and the model/scheduler self-tests are the selected cold checks.
Retained check outcomes are under `artifacts/0.5.8-10/`.

On 2026-10-13, with the operator's explicit authorization, this archive was also
built as a Linux server (autoreconf on the host; the available WSL distribution
still lacks it) and deployed to the operator's self-hosted supernode together
with the v7.3.2 observer script and an `--observer-only` unit. One bounded TCP
probe (`0xffff` length prefix plus four kilobytes) had killed the previous
deployment's process — systemd recorded SIGSEGV and restarted it — and left the
new binary running with its restart counter unchanged. Legitimate behaviour was
re-checked on the live service afterwards: QUERY_PEER answered on UDP and on the
TCP aux socket including split and back-to-back frames, real clients
re-registered, and the coordinator still answered PROBE, PROBE7 and XPROBE while
ignoring experimental room commands.

Patch 57 came out of that deployment: on an isolated loopback instance the
pre-fix binary was killed by glibc's stack-smashing check after a single
registration datagram carrying an oversized `auth.token_size`. The new length
checks were confirmed against the same datagram on the rebuilt binary, which
stayed up. Remote exploitation beyond that crash, heap-overflow evidence from an
instrumented harness and any federated deployment were not reproduced, and
interoperability with mixed client versions still depends on the operator's own
sessions.
