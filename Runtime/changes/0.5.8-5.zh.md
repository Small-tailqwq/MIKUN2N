# Runtime Change: 0.5.8-5 — 稳定租约与有界恢复流量

Version: 0.5.8-5

> [English](0.5.8-5.md) | [简体中文](0.5.8-5.zh.md)

## 问题

十五小时日志显示就绪反复失效、反复探测离线身份及已建立路径恢复脆弱的问题。

## 改动记录

<a id="patch-50"></a>
### 补丁 50

0.5.8-5：修复十五小时客户端日志暴露的浪费与脆弱性。IPv6 的固定两秒保活对应 6.5 秒租约，租约还依赖对端探测，仅能容忍约两次连续丢失。在约 5% 探测丢包下，路径仍可用时就绪却过期 65 次，每次都使 DATA 走 supernode 并重启 IPv4 校准。保活按丢失情况调度，在任一租约临近结束时每 500 ms 重试，收到 PONG 恢复两秒节奏。IPv6 连续不可用十五秒后才恢复 IPv4 扫描；IPv6 承载 DATA 时保持可用 IPv4 路径温热，短暂缺口回退该路径而非中继。
IPv4 已建立路径接收端静默时，保留条目和获胜 worker socket 二十秒，期间中继并每秒探测旧端点；此前关闭 socket 会使短暂中断也必须完整重打洞。pending 条目按 last_seen 过期，不受上游十六条阈值限制。三十秒既未发包也没有 supernode 答复的身份停止打洞并降低查询频率；一个晚上曾累计同一主机十五个离线身份，各有完整预算。IPv4／IPv6 组播之外的组 MAC（LLDP、STP）在 TAP 丢弃，不再成为永久 pending peer。迟到 bank 计划仅由活跃校准接受，没有 worker 的喷射不扣轮数。APDM 协调错过后先免费重校准两次，间隔十秒，然后本轮回退单 socket 扫描；该扫描曾连续 39 轮、每轮约 11,600 包均未连接。一次只执行一项重扫描，打洞结果日志带对端 MAC。
Supernode 可选的 mikun2n_relay_kbit 和 mikun2n_broadcast_pps 仅限制中继 DATA，控制消息不受限。争用时每个发送 edge 平分配额，空闲时可借用带宽。两者默认均为 0，即不限；get_relay_stats 报告限制及丢弃／借用计数。不改变线协议，IPv6 保持第 3 代，混合版本可互通。离线回归覆盖保活调度、离线身份检测与中继策略，真实配对和服务端部署尚未验证。
