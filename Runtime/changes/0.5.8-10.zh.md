# Runtime 改动：0.5.8-10 — supernode 输入与身份边界

Version: 0.5.8-10

> [English](0.5.8-10.md) | [简体中文](0.5.8-10.zh.md)

## 问题

TCP 辅助套接字的两字节长度前缀（如 `0xffff`）会在接收边界校验之前回绕期望帧长，
使随后的接收写越帧缓冲区；未注册或未完成帧的连接可能
无限占用连接名额。中继载荷未绑定到其声明的源 MAC 所注册的传输连接。
知道联邦名的发送者可以引入联邦成员，而不受管理员配置的 peer 名单限制。

## 改动记录

<a id="patch-56"></a>
### Patch 56

TCP 长度先解码到 `size_t`，校验后再相加。保留现有的 2048 字节整帧上限：
扣除两字节前缀后，帧体最多 2046 字节。小于公共报头的帧体被拒绝。
每次接收要求 `position < expected`，并同时受整帧上限和实际缓冲区容量约束。
分段到达的前缀、帧体以及连续帧仍使用原有状态转换。

新连接须在 60 秒内注册；未完成帧从第一个字节起限时 15 秒。使用单调时钟，
在下一次循环检查期限（select 最多等待十秒）。只有成功绑定到该连接的本地注册
才清除初始期限。已注册的空闲客户端继续使用现有注册过期机制。连接名额已满
时接收后关闭新连接，分配失败也关闭新描述符；POSIX 下超过 `FD_SETSIZE` 的
描述符在进入 `FD_SET` 前被拒绝。

本地 PACKET 中继要求源 MAC 的注册匹配发送套接字和实际来源端点。关闭 TCP
连接时使其剩余注册绑定失效；通过验证的传输连接变更即使 IP/端口不变也更新绑定。
NAT 地址改变仍通过经验证的注册更新。这不改变开放集群的加入方式或可选载荷加密。

联邦流量必须来自 `supernode.peer` 显式配置的 IP/UDP 端口组合。双方须互相配置，
域名使用解析后的地址。未知来源的 REGISTER_SUPER 以及缺少 supernode 标志的
联邦报文被拒绝；无 peer 配置时关闭联邦入口。ACK 通告的成员不扩展白名单，
更新成员前先检查 ACK cookie。联邦名仍须一致。这是端点白名单，不是抵御已加白
来源地址伪造、链路攻击或受信服务器失陷的密码学认证。自动发现成员改为管理员
显式控制。

<a id="patch-57"></a>
### Patch 57

解码 REGISTER_SUPER、UNREGISTER_SUPER、REGISTER_SUPER_ACK 与
REGISTER_SUPER_NAK 时，来自链路的 `auth.token_size` 先与
`N2N_AUTH_MAX_TOKEN_SIZE` 比较，再写入定长令牌字段；
REGISTER_SUPER_ACK 中备份 supernode 数组的条目数受调用方载荷缓冲区容量约束。
缺少这些校验时，单个未认证 UDP 报文可把约 2 KB 的攻击者数据写到
`process_udp` 栈上 48 字节令牌字段之后。

## 配套协调器

v7.3.2 参考协调器将活跃 ID 绑定到端点，并提供用于地址变更的随机所有权令牌。
REPORT7 不再创建成员，也不能由其他端点在无令牌时替换成员。客户端仅在内存
保存令牌，并检查协调回复的服务器来源。生产观察服务使用 `--observer-only`，
保留 PROBE/PROBE7/XPROBE，不创建实验房间。见[参考协议](../../tools/natpunch/README.zh.md)。

## 验证与部署

选定的冷检查包括本地原生与参考客户端构建、现有 wire/IPv6 和协调器回归，
以及模型/调度器自测。检查结果保存在 `artifacts/0.5.8-10/`。

2026-10-13，经管理员明确授权，本归档也在主机上（现有 WSL 发行版仍缺
autoreconf）构建为 Linux 服务端，连同 v7.3.2 观察脚本和 `--observer-only`
服务单元一起部署到管理员自建 supernode。同一支有界 TCP 探针（`0xffff`
长度前缀加四 KB 数据）曾令旧部署进程被 systemd 记录为 SIGSEGV 并重启；
换成新二进制后同一探针不再影响进程，重启计数不变。随后在实机上复核了
正常行为：QUERY_PEER 在 UDP 与 TCP 辅助套接字上均有应答，包括前缀/帧体
分段与连续多帧；真实客户端重新注册成功；协调器仍应答 PROBE、PROBE7 与
XPROBE，并忽略实验性房间指令。

Patch 57 来自这次部署：在隔离回环实例上，修复前的二进制在收到一个携带
超大 `auth.token_size` 的注册报文后被 glibc 的栈破坏检测终止。重新构建后
用同一报文复核，新增的长度校验使进程保持存活。该崩溃之外的远程利用、
插桩 harness 得到的堆溢出证据以及任何联邦部署均未复现；不同客户端版本间的
互操作验收仍取决于管理员自己的实机使用。

## 2026-10-16 本地维护构建（未发布）

本地 `get_nat` 响应增加可选字符串 `ipv6_status`、`ipv6_address_kind` 和
`ipv6_mapping`，只读取已有套接字、地址映射和好友往返验证结果，不发送数据，
不改变计时器、系统网络设置、链路协议代次或 0.5.8-10 版本号。

仅有全局地址时保持待验证。新鲜的地址探测结果可区分端点未变、仅端口转换和
IPv6 地址转换；后者无法进一步区分有状态 NAT66 与 NPTv6。往返和映射证据
30 秒后过期，现有源路径探测持续失败时显示不可用。UI 不沿用超过 12 秒的
旧报告，保留 IPv4 信息；IPv6 开关关闭时隐藏附加区。旧运行时仍兼容，显示
状态未报告或待验证。

验证：原生构建；仅操作模拟内存且零发送的 `tools/tests-ipv6.exe --status-only`；
WPF 编译零警告、零错误；隔离的两主题卡片渲染和 90 项解析/展示检查。
未操作真实 edge、节点、网卡或防火墙。原生构建仍有既存的
`tools/n3n-benchmark.c` 未使用变量警告。
