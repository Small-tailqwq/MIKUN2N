# Runtime Change: 0.5.1 — Apply the configured Windows metric

Version: 0.5.1

> [English](0.5.1.md) | [简体中文](0.5.1.zh.md)

## Problem

Automatic interface metrics override the configured value and can route game broadcasts outside TAP.

## Recorded changes

<a id="patch-17"></a>
### Patch 17

0.5.1 fixes the metric option being silently ignored on Windows. Setting MIB_IPINTERFACE_ROW.Metric without clearing UseAutomaticMetric let Windows keep calculating the metric from link speed. This affects LAN games: the 224.0.0.0/4 and 255.255.255.255/32 routes exist on every adapter with equal RouteMetric, so interface metrics break the tie. The physical adapter's lower default metric sent game-room broadcasts outside the tunnel. Return UseAutomaticMetric to Windows when closing the tunnel. Observed verification: metric=1 previously left the effective metric at 25; afterward it became 1 and the preferred 255.255.255.255 egress switched from the physical adapter to TAP.
