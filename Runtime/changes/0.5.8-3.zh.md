# Runtime Change: 0.5.8-3 — 约束重放并澄清诊断

Version: 0.5.8-3

> [English](0.5.8-3.md) | [简体中文](0.5.8-3.zh.md)

## 问题

按时间保留已完成 ID 可能在负载下重新允许重复交付，诊断别名也掩盖方向性限制。

## 改动记录

<a id="patch-48"></a>
### 补丁 48

0.5.8-3：纠正诊断并约束负载下的重复交付。移除过时的 oversize_fallback 计数、重复的 ipv6_tx_udp_bytes 别名和按代次推导的 ipv6_fragmentation 标志。为 API／原始诊断使用者保留已验证出站尺寸及对端通告的接收上限，后者不是反向路径测量值。将 64 项、按时间清理的已完成 ID 缓存替换为 1024 ID 滑动重放窗口：活跃分片流中移出窗口的 ID 持续被拒绝，持续流量不能重新触发重复交付。两秒空闲过期仍兼容旧第 3 代发送端。发送端新 ID 在 edge 会话内 peer 重建时保留。只有 edge 首次接受有效分片时才分配重组存储，并在会话／peer 销毁时释放；supernode 不分配这些缓冲区。IPV6_DONTFRAG 失败输出普通警告。原生回归由 make 构建，覆盖高速 ID 复用、有界乱序、分片、会话变化及延迟分配生命周期。IPv6 仍为第 3 代，与 0.5.8-2 兼容。
