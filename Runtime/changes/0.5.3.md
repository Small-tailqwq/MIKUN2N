# Runtime Change: 0.5.3 — Finish classification and coordinate both peers

Version: 0.5.3

> [English](0.5.3.md) | [简体中文](0.5.3.zh.md)

## Problem

Slow classification and independent role selection can leave both peers scanning with incompatible timing.

## Recorded changes

<a id="patch-22"></a>
### Patch 22

0.5.3 moves the five NAT samples from second-scale wall-clock scheduling to a 250 ms monotonic schedule. To retain reliable filtering classification, the first round retries cross-port probes three times within 750 ms before contacting B. Later rounds advance A/B at 250 ms each. Sampling normally finishes in about three seconds, within the five-second native-direct priority window.

<a id="patch-23"></a>
### Patch 23

0.5.3 prevents freezing Tier 1 roles until NAT classification is complete or unavailable, then locks each round's strategy. Layered must complete 63 attempts and scanner/anchor 88, still bounded by 25 seconds and 12,000 packets. This avoids assigning both endpoints scanner before the five-sample classification finishes and avoids stopping at 69/71 ticks because the loop is slightly slow.

<a id="patch-24"></a>
### Patch 24

0.5.3 reports the NAT summary and edge-lifetime nonce through optional aflags extensions on existing QUERY_PEER/PEER_INFO messages. Only after receiving both summaries does the supernode issue a shared generation, complementary roles and a GO delayed by 1500 ms. Old edges ignore the extension. A new edge on an old supernode falls back to a locked local strategy after four seconds. The supernode validates the reported MAC, source socket, sample ranges and nonce, rejecting forged summaries.
