# Runtime Change: 0.5.5 — LAN priority, bounded retries and volatile mappings

Version: 0.5.5

> [English](0.5.5.md) | [简体中文](0.5.5.zh.md)

## Problem

Missing LAN candidates, resettable budgets, unstable UI state and volatile port allocation obscure or waste connection attempts.

## Recorded changes

<a id="patch-27"></a>
### Patch 27

0.5.5 fixes automatically discovered local addresses not being included in REGISTER_SUPER. Both endpoints exchange their actual LAN IP:port candidates through the supernode while retaining multicast discovery. Peers on the same LAN no longer enter NAT4 worker banks prematurely because of multicast routes, firewalls or startup order. Enhanced punching calibration also waits for the entire five-second native/LAN direct window, avoiding allocation of 25 temporary sockets while direct connectivity is already underway.

<a id="patch-28"></a>
### Patch 28

0.5.5 moves failure budgets from temporary peer fields, which cleanup/recreation could erase, to edge-session records keyed by peer MAC. Automatic punching runs at most three rounds, then explicitly reports failed and stays on pSp instead of repeatedly returning to round 1. Bank coordination timeout permits legacy fallback only in that round; the next round recalibrates instead of remaining stuck in fallback. Cancelling relay through management explicitly clears this record for a two-ended manual retry.

<a id="patch-29"></a>
### Patch 29

0.5.5 adds the terminal main-window state “pSp relay (punching failed)” and a context-menu action to restart punching on both endpoints. It also recognizes n3n's invalid transop ID and reports mismatched connection keys/encryption modes as configuration errors instead of network punching failures.

<a id="patch-30"></a>
### Patch 30

0.5.5 maintains the online-friend list incrementally instead of rebuilding ItemsSource on every poll. Hide horizontal/vertical scrollbars while preserving wheel scrolling, truncate long nicknames with an ellipsis and show the full name on hover. Virtual IPs can be copied through the context menu. A link-state change closes the old menu to prevent repeated operations against stale P2P state.

<a id="patch-31"></a>
### Patch 31

0.5.5 adds volatile classification to bank calibration, corresponding to natpunch v7.3.1's volatile mode. Classify MIKUN2N_BANK_MODE_VOLATILE when sampled ports span at least 192 without a dual-bank structure, or when at least one quarter of workers change their same-socket mapping by more than 96. Such a NAT assigns ports randomly within a window. Previously it entered symmetric and collapsed both banks to the newest sample: observed banks=4393/4393 and spread=15 against an actual allocation window of roughly 500, making a hit impossible. The volatile model sets bank1/bank2 to the observed window's lower edge and midpoint, tiling upward, and carries the measured span in spread for the peer's predicted lane. Target generation already handles VOLATILE as hard and adds a tail lane; no wire change is needed, and supernode validation [CONE,FAST] already includes the value.
