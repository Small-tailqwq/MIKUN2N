# Runtime Change: 0.5.7 — 实验性 IPv6 与中继统计

Version: 0.5.7

> [English](0.5.7.md) | [简体中文](0.5.7.zh.md)

## 问题

仅 IPv4 会合无法利用 IPv6 可达性；NAT66、路径尺寸和非对称就绪需要专门处理，中继总量也需要逐对归因。

## 改动记录

<a id="patch-38"></a>
### 补丁 38

0.5.7：实验性 IPv6 对端传输，默认关闭。仅 IPv4 的会合通道无法利用游戏客户端之间可达的 IPv6 路径。独立的 IPv6-only UDP socket 通过匹配的修改版 supernode 通告全局候选地址与会话 token。MTU 尺寸的挑战／响应探测确认路径，周期探测在 6.5 秒没有确认后使路径过期。地址变化使旧路径失效，发送失败或超大包使用原有 IPv4 路由。保留现有 IPv4 NAT4 worker socket、局域网直连优先级及强制中继策略。候选刷新保留已建立的 IPv4 目的端点；IPv6 回退时，正常的 last_p2p/timeout 检查删除过期 IPv4 路径并选择 supernode，近期确认的 IPv4 路径在该检查使其过期前仍可使用。get_edges 暴露传输类型和 IPv6 RTT。TAP／游戏地址仍为 IPv4，不增加 IPv6 supernode 监听或中继。每个客户端选择一个全局候选，已验证 IPv6 优先，不与 IPv4 RTT 比较选路。Windows 编译通过，真实 IPv6 联机和 Linux 部署尚未验证。

<a id="patch-39"></a>
### 补丁 39

0.5.7：IPv6 探测响应跟踪与运行状态。单个挑战可能在响应返回前被重试替换。为 6.5 秒路径窗口保留最多八个独立探测，保持发送节奏，并按实际探测计算 RTT。记录响应窗口耗尽。探测发送失败会使 IPv6 路径失效、报告 socket 错误，等待十秒再重试；本地地址刷新独立运行。get_nat 报告 ipv6_enabled，使客户端能区分配置请求与运行时确认。

<a id="patch-40"></a>
### 补丁 40

0.5.7：主动启用的 IPv6 测试诊断。MIKUN2N_IPV6_DIAGNOSTICS=1 记录本地候选选择与绑定错误、对端候选／查询状态、探测槽与匹配 RTT、路径过期／回退原因，以及每十秒的流量／拒绝计数。不记录会话 token、挑战值或报文载荷。私有测试客户端同时用 UTC 和单调时间戳采集事件，上传另需每次连接明确同意的独立弹窗。

<a id="patch-41"></a>
### 补丁 41

0.5.7：NAT66 到公网 IPv6 的兼容性。客户端日志显示，仅有可路由 ULA 的主机即使对端具备公网候选，也从未打开 IPv6 socket。可路由 ULA 可以绑定 socket 并通过匹配的 supernode 通告会话，仍优先选择本地全局地址。ULA 通告用于标识，不能作为互联网探测目的地。绑定会话的入站 PING 触发对其公网来源的限频验证；只有 MTU 尺寸的 PONG 匹配本端待决挑战、目标地址／端口及 6.5 秒窗口，才选择该端点。通告候选与已验证路径分离，刷新通告保留 NAT 映射，会话／地址变化则使其失效。DATA 仍仅接受已验证端点。诊断暴露 NAT66 能力、通告／选中地址、来源检查与路径选择。NAT66 需要两端客户端和 supernode 同时更新；公网端必须能接收首个 UDP 探测。尚未实现 NAT66↔NAT66 或 supernode 上的 IPv6 映射发现，真实 NAT66 联机仍待验证。

<a id="patch-42"></a>
### 补丁 42

0.5.7：超大数据包不破坏 IPv6 可达性。一次测试会话确认了 63 ms 的 IPv6 路径，却在 37 ms 后因 1593 字节的封装包超过已验证的 1418 字节而停用路径。持续的尺寸阻断停止出站探测并拒绝入站 DATA，却仍回答 PING，使远端继续使用本地已停用的路径。超大包逐包回退到已有 IPv4 路由，不改变已验证端点、过期时间或探测窗口。正常 IPv6 DATA 与保活继续，真实过期和发送失败仍使路径失效。超大包诊断记录 n3n／封装尺寸及路径保留，每个 peer 最多十秒一次，汇总中保留总回退计数。这不证明超过已验证尺寸的包能通过 IPv6 交付。线协议不变，支持 NAT66 的 supernode 仍兼容。

<a id="patch-43"></a>
### 补丁 43

0.5.7：按有方向的小组／MAC 对归因 supernode 出站 DATA。现有包计数无法识别哪些中继用户导致流量突增。成功的单播发送、按接收者复制的广播、联邦单播与联邦泛洪分别累计字节和包数。总体成功发送字节计数包含控制流量与封装，错误和流表溢出仍可观察。只读 get_relay_stats 支持分页，使用 64 位计数，每进程最多跟踪 8192 个键。不增加逐包写文件、载荷采集、线协议或客户端选路变化。可选本地服务端采集器每分钟保存检查点，并保留 30 天的小时汇总；统计口径与重启边界见 supernode/TRAFFIC.md。

<a id="patch-44"></a>
### 补丁 44

0.5.7：让 IPv6 检查适应较小路径并发现 NAT66 映射。热点客户端反复因 WSAEMSGSIZE (10040) 无法发送固定 1418 字节 UDP 探测。超大发送或一轮探测无响应后，预算降到 1232 字节，即 IPv6 最小 MTU 减去 IPv6／UDP 头。每个挑战记录精确尺寸，只有尺寸、来源端点、事务和有效期均匹配才能确定每个 peer 已验证的 DATA 预算。较大 DATA 逐包使用 IPv4，较小 IPv6 流量继续。可选 IPv6 STUN 观察者使用与对端流量相同的已绑定 UDP socket。验证来源／事务后的 RFC 8489 XOR-MAPPED-ADDRESS 回复通过已有 IPv4 会合通道通告，有效 30 秒、每十秒刷新；双方均可主动检查，不再要求 NAT66 端首个非请求探测穿过公网端防火墙。映射只是候选，DATA 仍须通过对端 PONG 验证，强制中继与局域网策略仍适用，IPv4 worker 目的端点不变。启动器异步解析可选私有配置 Ipv6StunHost；原生 MIKUN2N_IPV6_STUN_SERVERS 接收最多两个分号分隔的全局 IPv6 字面地址，使用 UDP 3478，不内置公共观察者默认值。诊断增加映射请求／结果／超时、接口 MTU、探测降档原因和 ipv6_checked_udp_bytes，不记录 token 或报文载荷。端点相关映射或 UDP 过滤仍可能阻止直连。使用匹配的客户端，无需修改 supernode 线协议。

<a id="patch-45"></a>
### 补丁 45

0.5.7：选择 IPv6 DATA 前要求双方接收就绪。混合客户端热点测试中，一端接受 1232 字节 PONG，另一端却拒绝 DATA；即使客户端匹配，探测预算收敛前仍分别拒绝 57／21 个启动包。线协议版本 2 的 PONG 在本端绑定来源的挑战成功后，通告有界的剩余接收租约。发送 DATA 同时要求该租约和本地已验证路径；接收保留来源／会话检查。旧线协议继续使用 IPv4。收到较小探测立即降低自己的验证预算，消除非对称 MTU 路径启动时的整尺寸超时。就绪过期回退 IPv4，诊断区分路径已验证与 DATA 就绪。IPv6 稳定五秒后暂停额外 IPv4 扫描，释放探索 worker，保留获胜 IPv4 socket 与目的端点。IPv6 丢失恢复有界扫描，并保留已消耗预算。管理接口增加 ipv6_wire_version 和 ipv4_scan_paused。IPv4 候选交换和现有 supernode 保持兼容，但所有参与客户端需升级。构建／wire 检查不能证明真实联机稳定性。
