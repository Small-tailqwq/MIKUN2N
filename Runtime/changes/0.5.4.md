# Runtime Change: 0.5.4 — Calibrated NAT4 worker banks

Version: 0.5.4

> [English](0.5.4.md) | [简体中文](0.5.4.zh.md)

## Problem

Dual-NAT4 peers need multi-socket mapping samples and coordinated attempts while preserving mixed-NAT behavior.

## Recorded changes

<a id="patch-25"></a>
### Patch 25

0.5.4 adds independent UDP worker banks for NAT4-to-NAT4. Each endpoint creates 25 temporary sockets and samples public mappings through observers on ports 21001/21002 on the supernode host, identifying cone reuse, single/dual banks, direction and port span. Summaries travel through QUERY_PEER. Only mutually addressed reports with matching generation and nonce that remain fresh cause the supernode to issue a shared monotonic GO. Both endpoints send valid n3n REGISTER packets concurrently from all workers at 100 ms ticks. A successful worker becomes the peer's data socket and the others close. An unsuccessful round cools down and recalibrates instead of repeatedly scanning an expired port model.

<a id="patch-26"></a>
### Patch 26

0.5.4 enables worker banks only when both final NAT summaries are APDM/NAT4. NAT3-to-NAT4, uncertain classifications and old supernodes retain the layered/local fallback path validated in 0.5.3. Dual NAT4 gains multi-socket sampling and parallel matching comparable to natpunch without changing mixed-NAT scenarios that performed well in this round.
