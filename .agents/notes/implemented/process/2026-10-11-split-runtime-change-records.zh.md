# Agent Note: 通过双语版本日志渐进披露运行时改动

Status: implemented

> [English](2026-10-11-split-runtime-change-records.md) | [简体中文](2026-10-11-split-runtime-change-records.zh.md)

## 问题

读者需要快速找到随包组件和构建步骤，贡献者需要查阅原生改动的理由与测试结果。把完整改动历史放进运行时 README，会让基本信息随着版本增加而越来越难找。

## 决策

[运行时概览](../../../../Runtime/README.zh.md)列出组件，链接[构建说明](../../../../Runtime/BUILD.zh.md)和[主题入口](../../../../Runtime/changes/README.zh.md)。`README.txt` 保留为简短双语入口，承接源码归档和组件声明中的已有引用。

实现历史位于 `Runtime/changes/<版本>.md` 及其 `.zh.md` 对照。每份记录说明问题与改动，测试结果紧邻相关实现。这些日志随运行时分发，描述对应版本的行为。`.agents/notes/` 下的 Agent Notes 记录持久决策，按自身生命周期与门禁维护。

57 项编号改动按版本归入 22 组双语日志。明确标明版本的条目按标签分组；第 1–5、34–37 项的版本未知，集中放在 `unversioned.md` 及译文中。`patch-N` 锚点保持稳定，供其他文档引用。每项编号记录用两种语言说明实现与证据。主题入口按机制提供链接，具体版本按文件名查找。

[项目内容清单](../../../../MikuN2N.csproj)将两种语言的概览、构建说明及所有改动日志 Markdown 复制到构建与发布输出。[发布打包脚本](../../../../tools/package-release.ps1)检查这些文件是否齐全。[更新器](../../../../Services/UpdateService.cs)安装子目录，并在非递归清理被替换的 `.update-old` 文件时包含 `Runtime/changes/`。

[Agent Notes 采纳记录](2026-10-11-adopt-agent-notes.zh.md)说明决策笔记的语言、生命周期、门禁和代理接入选择。技术文档通过对应版本和语言的日志引用运行时改动。

## 曾考虑的替代方案

**继续向运行时 README 追加。**可以在单个文件内阅读，但查组件信息也要承担完整历史的阅读成本，每次发布都会增长。

**把完整清单移动到单个 changelog。**概览缩短了，但链接背后仍是无限增长的详细文档。按版本拆分可限制每个阅读单元的规模。

**每个编号补丁单独成文件。**检索更细，但会把一次交付拆到许多文件中，使成对翻译维护更分散。版本分组保留逐补丁稳定锚点，仍能精确引用。

**把全部实现历史存为活跃 Agent Notes。**笔记的维护规则要求事实跟随当前代码更新，版本日志则需要保留历史行为。随包分发笔记还会把内部流程指引带入运行时包。

## 后果

读者可以从概览和主题入口找到相关版本。新增版本时更新一组双语记录和相关主题链接，概览保持简短。两种语言都随运行时分发。

运行时日志不在 `agent_notes.py` 的检查范围内，双语内容、链接和随包文件需要人工核对。了解当前行为时，需要查阅最新的相关记录和技术文档。
